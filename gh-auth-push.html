GH auth push.

Push the open folder to a GitHub release. Paste the command, enter a release name, and files upload one by one with live speed. Same name again skips files already on that release.

The command
PowerShell · gh auth · GitHub release

Paste it in the repo folder.

Shift+right-click the cloned repo, open PowerShell, and paste. The line runs itself and asks for the release name. Part suffixes stay intact. A second run with the same name skips files already uploaded.

powershell / gh

What it does: cleans filenames, keeps .part1.rar and .7z.001 suffixes, asks for a release name, then uploads the open folder one file at a time. The line shows percent and MB/s. A second run with the same name prints SKIP for files already on the release, then prints the full release link. Needs gh auth login once.

Live note
gh auth login

Run gh auth login once in PowerShell. Check with gh auth status. The command uses that login. It does not ask again.

How to use

Five steps. Then it uploads.

01

Login once

In PowerShell run gh auth login. Check with gh auth status.

02

Open the folder

Shift+right-click the cloned repo. Choose Open in Terminal or Open PowerShell window here.

03

Paste the command

Copy the command box and paste it. It runs itself and asks for the release name.

04

Enter the name

That tag is created if missing. The same name on a later run resumes the same release.

05

Let it finish

Each file shows percent and MB/s. The full release link prints at the end.

Only files in the open folder upload. Hidden files and faceupaldo.txt are skipped. .part1.rar and .7z.001 suffixes are not renamed. If the window closes early, paste the command again and enter the same release name.

faceupaldo.txt
